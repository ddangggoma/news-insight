# 독자 웹 런북 (R4)

로그인 없이 누구나 여는 화면입니다. **탐색**(`/`)에서 기술 분야·DX 사업부로 기사를 좁혀 읽고, **레이더**(`/radar`)에서 기간별 흐름을 봅니다. 분류는 P4(분야 15·테마 75·사업부 6·영향·범위·관련도)를 그대로 씁니다.

## 1. 구조

```
브라우저 ──HTTPS──▶ Caddy(8700) ──▶ web(Next.js) ──내부망 + X-Public-Key──▶ api(/api/public)
                    │  /              : 인증 없음 (탐색·레이더·다이제스트·RSS)
                    │  /console*      : Basic Auth (기존과 같음)
                    │  /api/public*   : 외부에서는 항상 404
                    │  /api/admin*    : 외부에서는 항상 404
```

- 독자 API(`/api/public`)는 웹 서버만 호출합니다. 콘솔 키와 다른 `PUBLIC_API_KEY`를 씁니다. 공개 페이지가 콘솔 권한을 갖지 않게 하려는 것입니다.
- `PUBLIC_API_KEY`가 비어 있으면 독자 API는 503을 돌려주고, 독자 화면은 "기사를 불러오지 못했습니다"를 보여 줍니다. 콘솔은 영향을 받지 않습니다.
- 응답은 본문 전문·소스 키·검증 단계·비용 같은 운영 정보를 담지 않습니다. 원문은 링크로만 연결합니다.

## 2. 처음 설정 (1회)

`.env`에 키를 넣고 다시 띄웁니다. 값은 아무 무작위 문자열이면 됩니다.

```bash
echo "PUBLIC_API_KEY=$(openssl rand -hex 24)" >> .env
scripts/dev.sh up
```

로컬 개발에서는 API와 웹에 같은 값을 줍니다.

```bash
PUBLIC_API_KEY=dev-public scripts/dev.sh api-dev
PUBLIC_API_KEY=dev-public scripts/dev.sh web-dev
```

## 3. 화면

| 경로 | 내용 |
|---|---|
| `/` | 탐색. 범위(DX 관련+의존 기술 / DX만 / 전체), 분야·테마·사업부·영향·트랙·지역 필터, 이슈별 1행 피드, 키워드·분야·사업부·영향 인사이트, 최신 다이제스트 띠 |
| `/?field=ai_data&business=mx&period=30d` | 필터는 모두 URL에 남아 그대로 공유됩니다. 같은 축 안은 OR, 축 사이는 AND |
| `/items/{id}` | 기사 상세. 목록에서 열면 오른쪽 시트, 링크로 열면 전체 페이지. 같은 이슈의 다른 보도, 교차 신호(같은 arXiv·DOI·저장소) |
| `/radar` | 이번 주 레이더로 이동. `/radar?period=month`는 이번 달 |
| `/radar/week/2026-W40` | 분야 × 사업부 히트맵(표 보기 포함), 칸 상세, 분야 모멘텀, 관심 대비 실체 산점도, 키워드 변화 |
| `/digests`, `/digests/2026-10-04` | 다이제스트 목록과 본문 (모델·비용 정보 없음) |
| `/feed.xml` | 다이제스트 RSS (최근 20개) |

## 4. 숫자 읽는 법

- **기간:** 탐색의 1일·7일·30일은 지금부터 거꾸로 센 구간, 레이더는 KST 달력 기준(주 = ISO 주, 월요일 시작)입니다.
- **증감:** 직전 같은 길이 기간과 비교한 비율입니다. 직전 기간이 0건이면 "–"(탐색 키워드는 "신규")로 표시합니다. R3 롤업이 들어오면 통계적 급상승 점수로 바뀝니다.
- **히트맵 칸:** 그 분야·사업부로 분류된 기사 수입니다. 한 기사에 사업부가 여러 개면 각 칸에 한 번씩 셉니다. 사업부가 없는 기사는 "미지정" 열에 들어갑니다.
- **관심 대비 실체:** 가로는 뉴스·커뮤니티, 세로는 논문·오픈소스의 증감률입니다. 직전 기간이 0건인 분야는 비교할 수 없어 빠집니다.
- **이슈:** P4 묶음 단위입니다. 묶이지 않은 기사는 그 자체로 하나의 이슈로 셉니다.
- **공개 대상:** 카드가 만들어지고 현재 분류 리비전으로 분류된 기사입니다. V6 전 Canary 소스의 기사도 포함합니다.

## 5. 캐시

웹 서버가 독자 API 응답을 캐시합니다(탐색 5분, 다이제스트·레이더 10분, 분류 체계 1시간). 새 카드가 들어와도 최대 5~10분 뒤에 보입니다.

## 6. 문제 해결

| 증상 | 확인 |
|---|---|
| 모든 독자 화면이 "불러오지 못했습니다" | web·api 양쪽에 같은 `PUBLIC_API_KEY`가 들어 있는지. API 로그에 401이면 값 불일치, 503이면 api 쪽 미설정 |
| 탐색은 되는데 다이제스트 띠가 없음 | 아직 발행된 다이제스트가 없거나, 최신 다이제스트를 읽다 오류가 났습니다(웹 로그에 `latest digest failed`). 피드는 계속 보입니다 |
| 필터를 골라도 0건 | 범위가 "DX 관련 + 의존 기술"이면 `excluded`·`irrelevant` 분류는 빠집니다. 범위를 "전체"로 바꿔 보세요 |
| 레이더 칸이 대부분 비어 있음 | 카드가 아직 현재 `TAXONOMY_REVISION`으로 분류되지 않았습니다. `docs/runbooks/stories-classification.md`의 재분류 절차를 확인하세요 |
