# 수집처 확장 적용·실수집 테스트 결과

2026-10-05 KST. 통합검토서와 사용자의 최신 의견인 **언어 필터 없는 GitHub 전체 Trending**을 기준으로 코드·카탈로그·운영 컨테이너에 적용했다. 계정 발급이나 유료 서비스 구매는 하지 않았다.

|---|---:|

47개는 뉴스 15, 연구기관 17, GitHub 목록 6, 특허 1, 학술지 서지 대안 8로 구성된다. **채널 수는 독립 발행사 수가 아니다.** GitHub의 6목록은 한 플랫폼이고, pv magazine 두 판은 같은 그룹, Crossref 학술지 8채널의 원발행사는 Springer Nature다.

새 소스는 V3 후보로 시험 수집되며 스케줄러가 후속 수집한다. V6 활성 소스로 강제 승격하지 않았다. 24시간 안정성 평가와 최근 7일의 분류·번역 품질 평가는 후속 운영 지표가 필요하다. 최초 수집 주기는 `slow`의 6시간이며 변화·유휴 상태에 따라 조정된다. 신규 소스의 한국어 카드 **41건 ready 상태**도 DB에서 확인했다. 개별 카드 내용의 편집 검수와 UI 전수 검증은 별도다.

Rest of World는 기존 등록 소스여서 중복 채널을 만들지 않았다. The Register와 Tech.eu도 새 키를 만들지 않고 기존 소스를 복구했다. 국가와 테마를 `config.country`, `themes` 등에 보존하고 동일 발행그룹을 `publisher_group`으로 기록했다. 기존 `region`은 5개 권역이라 국가 세부 필드와 구분한다.

기관의 자체 보도자료는 연구 결과의 1차 설명이고 독립적인 평가가 아니다. Crossref는 DOI 서지 등록 경로이며 논문의 결론 검증이나 원문 이용권을 보증하지 않는다. 국가·발행사 태그 추가만으로 국가별 기사량이나 최종 추천의 균형이 자동 달성되지는 않는다. 뉴스·연구·GitHub·특허를 분리 집계하고 기사량·분류 결과·동일 발행그룹의 비중을 함께 평가해야 한다.

ETRI 최초 13건 중 5건은 과거 고정 글이다. 날짜 필터 보완 후에는 최근 8건만 수집하며, 기존 과거 항목은 프로젝트의 archive 조건에 따라 카드·독자 화면에서 제외된다. RSS는 과거 항목도 원장에 남길 수 있으므로 저장 건수와 최근 기사 수를 혼동하지 않는다.

EPO의 20건 최초 시험 수집은 누적 네트워크 시간이 10,003ms여서 안정성 평가의 10초 기준에 근접했다. 운영 설정을 회차당 10건으로 낮춘 재실행에서는 6,262ms였고 중복 저장이 없었다. 장기 지연은 추가 관측이 필요하다.

## GitHub 전체 Trending

언어별·자연어별 필터와 테마 사전 필터를 사용하지 않는다. **저장소/개발자 × 일간/주간/월간 6목록의 모든 표시 행**을 수집한다. 저장소의 언어는 설명에 부가정보로 남긴다.

| 목록 | 일간 | 주간 | 월간 |
|---|---:|---:|---:|
| 저장소 | 12 | 21 | 23 |
| 개발자 | 25 | 25 | 25 |

총 131개의 목록별 항목과 지표 스냅샷을 확인했다. 기간 간 같은 저장소의 중복 등장은 각각의 순위 관측이므로 고유 저장소 131개라는 뜻은 아니다. 두 번째 실제 수집에서는 6개 모두 새 항목 0건이고 지표 스냅샷도 중복 생성되지 않았다.

순위·stars·forks·기간 증가 표시를 정수로 보존하며, 관측 시각은 지표 스냅샷에 기록한다. 발행일은 `null`이다. 뉴스의 발행일 검사와 별도로 순위가 있는 고유 식별자 최소 3개를 V3에서 검증한다. 구조 변경으로 행·식별자가 사라지면 성공한 빈 목록으로 처리하지 않는다.

이 구현의 전체 범위는 GitHub가 공개한 Trending 화면이다. 모든 공개 저장소의 전수 수집은 아니다. GitHub API ID에 의한 저장소 이전 추적, topics/license 보강, 개발자의 대표 저장소·Built by 관계는 아직 추가하지 않았다.

## 특허 범위

[EPO 공식 EPS 안내](https://www.epo.org/en/searching-for-patents/data/web-services/publication-server)와 [REST 규격](https://data.epo.org/publication-server/doc/EPS%20REST%20services.pdf)을 확인하고, 최신 공개일 목록 → 해당 주간 목록 → XML 서지를 읽도록 구현했다. 2026-09-30 주간 목록 6,134개를 확인했다. 운영은 그 목록의 앞 10건에 대한 시험 서지 수집이며 전체 주간·전 세계 특허 수집이 아니다. 문헌 전문·PDF는 저장하지 않는다.

공식 소개 페이지에는 7일 5GB, PDF에는 10GB 제한이 기재되어 서로 다르므로 더 작은 5GB 기준으로 보수적으로 운영한다. 현재는 소량 서지만 요청한다. EP 문헌 ID와 실제 공개일을 보존하지만 패밀리·출원인 정규화·법적 상태·세계 범위 검색은 이 시험 어댑터의 범위에 포함되지 않는다.

KIPRIS Plus·EPO OPS·USPTO ODP·JPO·Lens의 권한/키, WIPO 대량 제공 조건, BigQuery 프로젝트/비용 조건이 필요한 경로는 종전 검토서에 남겼다. EPO Linked Open Data는 소규모 탐색용이고 운영 백엔드용은 bulk 다운로드를 권장하므로 반복 운영의 대체 API로 채택하지 않았다. [EPO 공식 이용 범위](https://www.epo.org/en/searching-for-patents/data/linked-open-data)

## 전체 운영 상태와 검증의 한계

최종 운영 스냅샷은 등록 원장 **1,356개**다: 활성 46, 후보 1,242, 일시중지 32, 폐기 36. 활성 46개의 최신 기록은 성공 42·304/변경 없음 4였다. 하지만 전체 원장 최신 기록에는 OpenAlex 한도 실패 39개와 기존 접근/MIME/크기/시간 초과 실패가 남아 있으므로 **전체 수집처가 모두 정상이라는 결론은 아니다.**

OpenAlex의 기존 429 이력은 제거하지 않았다. 현재 운영 코드에는 공유 제공자 예산·Retry-After·전체 제공자 백오프·하루 단위 수집 간격이 이미 있으며 이를 유지했다. 당일 한도나 제공자 응답을 무시해 강제로 성공 처리하지 않았다. Crossref 대안은 서지 범위가 다르므로 OpenAlex의 전체 기능을 대체한다고 표시하지 않는다. 실패 이력별 조치는 [전체 실패·대안 목록](source-crawl-2026-10-05/existing-failure-alternatives.csv)에 기록했다.

기존 연구·뉴스의 편중과 SNS 주요 인물 커버리지에 대한 초기 검토는 별도 검토서의 과제로 유지한다. 이번 적용의 직접 추가 범위는 뉴스·기관·GitHub·학술 서지·EP 특허다. X/Reddit의 유료·승인·인증 조건을 해결한 것으로 표시하지 않는다.

API·worker·scheduler의 새 이미지를 배포하고 API health `ok`, API·worker·web·DB·Redis의 건강 상태를 확인했다. DB 스키마 변경은 없다. 이전 API 이미지는 `news-insight-api:before-source-expansion-20261005`로 보관했다. 기존 사용자 변경인 Caddyfile은 수정하지 않았다.

테스트 650개에는 실제 별도 PostgreSQL 테스트 DB와 Redis DB 15 검증이 포함된다. 27개 건너뜀은 `RADAR_QA_DIR`가 필요한 별도 planted radar QA이며 수집 파서 실패가 아니다. Ruff·mypy(145개 모듈)·`git diff --check`도 통과했다. 실수집 성공은 이번 요청 시점의 증거이며 미래의 접근 성공·품질을 보장하지 않는다.
