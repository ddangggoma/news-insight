## 1. 카드 생성 실패 — 원인과 해결 (완료)

**원인.** Antigravity가 배치를 덜 돌려준 게 아니었습니다. 실패 4,643장 중 엔진 출력 누락은 5장뿐이고, 4,638장이 보존 검증(원제의 숫자·모델명이 번역에 남았는지)에서 걸렸습니다. 대부분 오탐이었습니다.

- 링크 조각: 소셜 글의 `https:// blog.jetbrains.com/go/2026/04/ 28/` → "2026, 04, 28 손실"
- 한중일 문자: `\w`가 한자·가나까지 잡아 "50万高端SUV音响PK"를 하나의 식별자로 봄
- 저장소 제목의 사용자 이름(`ald0405/whoop-data`), 날짜 코드(`_20240711`), 도메인
- 단위 변환을 모름: 81,000 = 8만 1천, 100 million = 1억, 800K = 80만, 02 = 2, 3rd = 3주년, COVID-19 = 코로나19
- 실패 카드는 독자 화면에 나오지 않았습니다.

**해결(#37).** 검사를 값 비교·한국어 표현 인정으로 바꾸고, 프롬프트에 숫자·버전 보존 규칙을 넣고, 재시도 때 빠진 표기를 `keep`으로 알려 주며, 마지막 시도는 카드를 버리지 않고 손실을 기록합니다.

**실측(3번 실패한 카드 60건을 실제 Antigravity로 재실행).** 예전 검사 11건 → 새 프롬프트·검사 41건 → `keep` 재시도 후 59건 통과.

남은 실패는 대부분 진짜 누락(나이·가격·통계 수치를 뺀 요약형 제목)입니다. 쇼핑 특가·SNS 통계 같은 무관 기사가 많습니다.

## 2. 로그 체계 (완료, #39)

| 무엇을 | 어떻게 바꿨나 |
|---|---|
| API 오류 | uvicorn이 평문으로 찍던 트레이스백을 JSON으로, 처리되지 않은 예외를 경로와 함께 `unhandled error`로 기록 |
| worker·scheduler | celery 핸들러를 JSON으로 통일, scheduler 이름 구분 |
| CLI(카드·다이제스트) | rich 상자 트레이스백 대신 JSON 한 줄(`command failed`) |
| Claude 실패 | `claude exited 1:`만 남던 것을 CLI가 준 이유("Not logged in", 한도 등)까지 기록(이번 PR) |
| 보관 | 컨테이너 로그 20MB × 5개(이전 무제한), 호스트 로그 20MB에서 회전, 배포 때 교체되는 컨테이너 로그를 `ops/logs/containers/`에 7일 보관(이번 PR. 이전에는 배포마다 사라짐) |
| 분석 | `scripts/dev.sh logs-report`: 오류 시그니처별 횟수·처음/마지막, API 경로별 상태·p50/p95, Celery 실패, 카드 실행 |
| 점검 | `scripts/dev.sh audit`: 수집·중복·카드·분류·이슈·DB·컨테이너, 심각도별 발견 사항 |

아직 남은 한계:

- postgres 로그에 데이터베이스 이름이 없어 테스트 DB 오류가 섞입니다(`uq_sources_key`의 `dup`은 테스트). `log_line_prefix`에 `%d`를 넣으려면 postgres 재시작이 필요합니다.
- 느린 쿼리 원인 추적용 `pg_stat_statements`가 없습니다.
- postgres·redis는 다음 재생성 때 로그 상한이 적용됩니다.

- **호스트 자원 부족이 가장 큼**:
  - Mac 32GB에 스왑 29GB를 쓰고 있고, 여유 메모리는 12%입니다.

  - Docker VM은 CPU 5개·8GB이고, daily-it-intelligence·din 컨테이너 11개가 함께 돕니다.
  - 그 결과 같은 쿼리가 3~10초로 들쭉날쭉합니다.
- PostgreSQL:
  - shared_buffers 128MB(기본값), 캐시 적중률 93.7%입니다.
  - 10/05 00:16 강제 종료·재시작으로 통계가 초기화돼 `items` 자동 analyze 기록이 없습니다. planner는 reltuples 99k를 써서 아직 큰 문제는 아닙니다.
  - 쓰이지 않는 인덱스 9개(제목 trgm 32MB 등)가 있습니다.
  - `item_cards` 순차 스캔 2억 2천만 행입니다.

### 3.8 컨테이너·배포

- `docker compose up -d --build`가 오늘 네 번 멈췄습니다. 새 컨테이너를 만들고 시작하지 않아 API·DB가 10~20분씩 내려갔습니다.
  - `init: true`(#36)로 좀비 프로세스 문제는 고쳤지만 멈춤은 계속됐습니다.
  - `scripts/deploy.sh`(#38)로 우회하고 있습니다. 두 번 써 봤고 정지 시간은 약 1분이었습니다.
- 개발 트리의 `verify`가 운영 postgres를 다시 만들던 위험은 가드로 막았습니다(#34).
- Docker 디스크: 이미지 14.8GB 중 10.3GB, 빌드 캐시 12.2GB가 회수 가능합니다.
