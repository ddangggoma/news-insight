# 수집처 검토 결과와 적용 전 제안

검토일: 2026-10-05 KST. 운영 기준선: 14:24:27 KST. 대상: NEWS_INSIGHT.

## 결론

**우선순위는 수집처 확대보다 데이터 선택·처리 구조의 교정이다.** 신뢰할 만한 발행처가 이미 다수 등록되어 있지만, 전사이트 사이트맵과 태그 검색이 처리량을 차지해 중요한 공식·전문 출처가 카드 생성에서 밀린다. 기술별 순위는 일부 업체의 제품 카탈로그에 좌우될 수 있다.

권장안은 **① 오래된·상시 문서 분리와 핵심 출처 복구 → ② 고정 프로젝트 기반 OSS 관측 → ③ 검증된 인물 RSS·공식 API와 업체 공시 보완**이다. X는 예산을 정한 선택 모듈, Reddit은 승인 후 도입 대상으로 둔다. 검토 중 운영 설정·카탈로그·DB 데이터·스케줄을 변경하거나 유료 API를 구매하지 않았다.

## 검증 범위와 한계

- 카탈로그 1,273개 전수 집계, 운영 DB 1,309개 전수 집계와 116,773개 항목의 집계 분석을 수행했다. DB의 추가 36개는 retired OSS 항목이다.
- 30개 기존 채널과 31개 대안·보완 경로에 총 61개 엔드포인트 요청을 수행했다. 60개 HTTP 200, Sony RSS 1개 403. HTTP 200에는 빈 피드·HTML·사이트맵도 포함되므로 모두 수집 적합 판정은 아니다.
- 기존 30개는 **채널 가용성 파일럿**이다. 각 채널의 기사 20건씩 사실 검증한 결과는 아니다. 전체 기사 정확도·전체 발행자 인지도에 대한 전수 인증은 하지 않았다.
- 운영 데이터의 최초 수집은 10월 4일 01:33 KST로 약 37시간이다. 아래 '7일 창'은 실제 7일 전체를 관측했다는 뜻이 아니다. 초기 백필과 카드 대기열이 분포에 크게 영향을 준다.
- 독자 후보는 ready 카드 + 현 분류체계 + DX 관련 + 현행 최신성 조건을 통과한 **이슈 묶기 전 항목 수**다. 실제 화면 노출·사용자 조회수·브리핑 발행량이 아니다. 현행 조건은 날짜 미상도 포함한다.
- 직접 요청은 이 기기의 네트워크에서 확인한 일회성 응답이다. 배포 컨테이너의 SafeFetcher·파서·robots 검사 통과, 지속 가동, 저장·요약·재배포 권리까지 보장하지 않는다.
- 외부 정책은 공식 문서를 확인했다. 불명확한 저장·LLM 처리 조건은 별도 도입 조건으로 남겼다. 공개 URL과 접근 성공만으로 허용 판정을 내리지 않았다.

## 1. 전체 데이터는 어디에 기울어 있는가

### 1.1 수집 방식과 처리 단계의 편중

| 구분 | 전체 항목 | 카드 | 독자 후보 |
|---|---:|---:|---:|
| 전체 | 116,773 | 70,118 | 22,243 |
| 사이트맵 | 62,838 (53.8%) | 50,680 (72.3%) | 9,635 (43.3%) |
| 뉴스 트랙 | 60,859 | 41,113 | 9,875 |
| 커뮤니티 트랙 | 42,427 | 23,370 | 8,518 |
| 연구·IP 트랙 | 8,560 | 3,185 | 2,312 |
| OSS 트랙 | 4,927 | 2,450 | 1,538 |

전체 항목의 44,257개(37.9%)는 발행일이 최초 수집일보다 30일 넘게 앞선다. 정규화 URL 기준 초과 사본은 7,868개(6.7%)다. URL 정규화 후에도 언어별 번역·같은 발표의 전재·업체별 브랜드 차이는 남을 수 있다.

개별 수집 채널의 상위 10개 점유율은 수집 기준 14.9%, 독자 후보 기준 28.4%다. HHI는 각각 63.6, 122.9(0~10,000 척도). **채널별 분산은 발행자·플랫폼 다양성과 다르다.** mastodon.social 하나가 독자 후보 4,161개(18.7%)를 공급한다. 59개의 태그 채널을 59개의 독립적인 전문 출처로 세면 안 된다.

표본에는 Infineon 부품 페이지, Zigbee 기기 지원 목록, Waymo 다국어 페이지가 들어 있었다. 날짜가 최근이라고 해도 신규 기술 사건이 아닐 수 있다. `lastmod`와 실제 기사 발행일을 구분해야 한다. 동일한 부품·기기 목록의 갱신이 기술 급상승으로 잡히지 않게 해야 한다.

62개 테마에 모두 후보가 존재하지만, 이것은 62개 테마의 정보가 충분하다는 뜻이 아니다. 예를 들어 단일 업체의 상품 페이지가 테마를 채우는 경우가 있다. 전체 테마별 수치와 최대 채널은 [테마 커버리지 CSV](source-review-2026-10-05/theme-coverage.csv)에 담았다.

### 1.3 지역과 업체를 해석할 때의 주의점

독자 후보의 출처 지역 표시는 global_en 50.0%, eu_other 29.3%, 한국 9.7%, 중화권 8.7%, 일본 2.3%다. 그러나 mastodon.social 채널은 eu_other로 기록되어 있다. **서버·운영사 소재지를 모든 글의 지역으로 물려준 결과가 섞여 있어, 유럽 정보가 풍부하다고 결론낼 수 없다.** 글 언어·저자 소재·기사 대상 지역을 분리하고 불명은 불명으로 표시해야 한다.

업체별 실제 기사 비중은 구조화된 업체 식별자가 없어 이번 집계에서 신뢰성 있게 산정하지 못했다. 현재 확인 가능한 것은 공식 채널 수와 해당 채널 기여도다. 업체의 뉴스룸·개발 블로그·자회사·개인 발언을 하나의 업체로 연결하는 엔터티 대장이 선행되어야 한다.

## 2. 신뢰성과 인지도: 무엇을 살리고 어떤 용도로 쓸 것인가

| 출처 유형·예시 | 현재 검증 근거 | 제안 역할 | 제한 |
|---|---|---|---|
| IEEE Spectrum | 공식 소개에 IEEE 발행·편집진·사람의 사실 확인 정책 명시. RSS 30건 파싱. 기사 표본에 World Bank 원자료 링크 확인 | 기술 전문 보도 핵심 후보 | 전체 글 정확도 보증 아님. 피드에 행사 링크도 있어 기사·행사 구분 |
| Ars Technica | 공식 소개에서 기술 전문 편집·운영 주체 확인. RSS 20건 | 독립 해설·검증 후보 | 과학 일반·비기술 콘텐츠 필터, 별도 이용조건 확인 |
| 전자신문·디일렉 | 기존 수집 및 RSS 실응답, 각각 30·50개 항목 확인 | 국내 산업·부품 보도 유지 후보 | 전문성·인지도는 별도 심층 등급 미확정. 광고·보도자료 구분 필요 |
| The Verge·TechCrunch·MIT Technology Review | RSS 실응답과 항목 확인 | 글로벌 보도 보완 | 명성만으로 우선 발행 금지, 일반 뉴스·스폰서·유료 접근 구분 |
| 삼성·Apple·NVIDIA·Google·Microsoft·OpenAI | 공식 도메인 RSS 확인 | 자사 발표의 1차 근거 | 성능·시장 우위는 외부 근거 필요 |
| GitHub 프로젝트 API | 5개 저장소의 JSON·식별자·라이선스 필드 확인 | 릴리스·활동 수치의 1차 근거 | stars는 품질·실제 채택의 증거가 아님 |
| HN·Mastodon·Reddit | 커뮤니티·반응 신호 | 탐색·사용 경험 | 익명 발언을 확정 사실로 승격하지 않음 |

인지도는 '국제적으로 알려짐'이라는 주관적 단일 점수보다 **확인한 기관 소속·출판 이력·편집 책임·개발 실적**을 노출하는 방식이 적합하다. 이번 확인은 IEEE·Ars 및 일부 인물의 정체성·전문성 근거 확보 수준이며, 1,273개 발행자의 인지도 전수 등급은 미확정이다. 전체 목록에 자동 신뢰 등급을 부여하지 않았다.

근거: [IEEE 소개·편집 정책](https://spectrum.ieee.org/about), [표본 기사](https://spectrum.ieee.org/electricity-theft), [Ars 소개](https://arstechnica.com/about-us/). Ars는 재사용 제한도 명시하므로 RSS 접근과 전문 저장·번역 발행 권한을 분리해 확인한다.

### 이미 있는 좋은 출처를 먼저 복구해야 한다

| 채널 | 운영 수집 항목 | 카드 상태 | 권장 조치 |
|---|---:|---|---|
| IEEE Spectrum | 30 | 카드 없음 | 핵심 출처 전용 처리 예산 |
| NVIDIA Blog / Developer Blog | 18 / 50 | 카드 없음 | 공식 기술 발표 우선 처리 |
| OpenAI News | 50 | 카드 없음 | 피드의 과거 1,245개 전체를 백필하지 않고 신규분만 처리 |
| Apple Newsroom | 20 | 카드 없음 | 기사 날짜·관련성 기준으로 처리 복구 |
| Samsung KR / Global | 0 / 0 | V0에 머묾 | V1 robots 타임아웃 재검증 제안 |
| Simon Willison 블로그 / Bluesky | 33 / 33 | 독자 후보 2 / 1 | 중복 통합 후 개인별 처리 기회 확보 |

삼성은 최신 실패 로그가 robots 요청 타임아웃이다. 이번 단발 요청에서 두 RSS가 각각 20·50건, robots.txt가 HTTP 200 및 전체 경로 허용을 반환했다. **출처 교체보다 기존 검증 재시도가 먼저**다. 실제 재시도·승격은 실행하지 않았다.

## 3. 실제 수집 가능한 대안과 채택 판단

상태를 `실응답 확인 / 조건부 / 보류`로 나눈다. '실응답 확인'은 운영 반영 승인이나 콘텐츠 재사용 권리 확정을 뜻하지 않는다. 전체 URL·응답·기존 등록 여부는 [대안 31개 CSV](source-review-2026-10-05/alternatives.csv), [원시 응답 요약](source-review-2026-10-05/endpoint-probes.json)에 있다.

| 대상 | 경로·실측 | 제안 | 개발·운영 조건 |
|---|---|---|---|
| FreeBSD | [공식 RSS](https://www.freebsd.org/news/feed.xml), 200·10건 | 전사이트 사이트맵 교체 후보 | 날짜·고유 ID 검증. 같은 newsflash URL의 fragment가 항목을 구분하므로 fragment 제거 정규화 주의 |
| Zigbee2MQTT | [공식 저장소 Releases](https://api.github.com/repos/Koenkk/zigbee2mqtt/releases?per_page=3), 200·3건 | 기기 DB 수백 페이지 대신 신규 릴리스 | 기존 github_releases 매핑 활용, 계정·프로젝트 식별 |
| OSS 고정 관측 | llama.cpp·vLLM·Home Assistant·Zephyr·OpenTelemetry API 모두 200 | 검색 발견과 고정 저장소 관측 분리 | 단일 객체 API 어댑터, 저장소 ID 통합, 스냅샷 |

| Mastodon | 현 #ai API 200·40건 | 광범위 태그 비중 줄이고 공개 전문가 계정 보완 | 인스턴스별 인증·정책, 원본 URI 중복 제거 |
| HN | [공식 API](https://hacker-news.firebaseio.com/v0/topstories.json), 200·500 ID | 98개 Algolia 채널의 중복 검색을 공통 수집으로 통합 | item ID별 상세 조회, 신규 시간 필터, 쿼리 태그를 출처 수로 세지 않음 |
| Hugging Face | 모델 API 200·3개, 블로그 RSS 873건 | 모델 동향을 GitHub OSS와 나란히 보완 | 모델과 코드 프로젝트의 단위 분리, 라이선스·다운로드 의미 확인 |
| 미국 업체 공시 | [NVIDIA SEC submissions](https://data.sec.gov/submissions/CIK0001045810.json), JSON 200 | 미국 상장업체 공시 보완 | CIK 대장·병렬 배열 파서·공시 링크 생성, 식별 가능한 User-Agent |
| 한국 업체 공시 | OpenDART 공식 공시검색 문서 확인 | 조건부 도입 | 인증키 필요. 이번에 인증 API 실응답은 검증하지 않음 |
| 연구 | Crossref JSON 200, arXiv cs.AI RSS 402건, Nature RSS 75건 | DOI·논문 ID 중심 통합 | 논문·뉴스·정정 구분. 프리프린트를 심사 논문으로 표기하지 않음 |
| 보안 | CISA KEV JSON 200 | 실제 악용 취약점의 공적 근거 보완 | vulnerabilities 배열 파서, CVE 연결, 날짜 필터 |
| 일본 기업 기술 | IIJ RSS 10건, LY 영문 RSS 50건 | 일본·네트워크/플랫폼 정보 보완 | LY 일본어 채널은 기존 등록. 영문 추가 시 번역 중복 통합 |
| LG·Sony | lgnewsroom.com/feed는 200이지만 0건, Sony 시험 RSS는 403 | 해당 URL 그대로는 채택 보류 | LG 공식 뉴스룸 HTML은 200. 목록 선택자·날짜·정책 검증 후 별도 후보 |

OpenDART는 [공식 공시검색 개발가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001), SEC는 [공식 API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)와 [접근 정책](https://www.sec.gov/about/developer-resources)을 확인했다. SEC는 전체 요청을 초당 10개 이하로 제한하며, 이 프로젝트에서는 훨씬 낮게 시간별 분산 수집하면 충분하다.

### X: 실제 도입 가능한 유료 선택지

공식 [사용자 게시물 API](https://docs.x.com/x-api/users/get-posts)를 사용한다. 사람별 사용자 ID를 확인하고 `since_id`로 새 글만 받으며, 불필요한 재게시·답글은 범위를 정해 제한한다. 페이지네이션·원문 문맥·수정·삭제·계정 변경·비용 상한을 별도로 처리해야 한다.

[공식 요금표](https://docs.x.com/x-api/getting-started/pricing)의 게시물 읽기는 건당 **$0.005**, 사용자 읽기는 **$0.010**다. 예를 들어 30명 × 일 5개 × 30일 = 4,500개를 읽으면 게시물 비용만 약 **$22.50/월**이다. 50명 × 일 10개라면 **$75/월**이다. 반복 조회·추가 리소스·세금·환율·LLM 비용은 별도이며 실제 글 수에 따라 달라진다. UTC 하루 내 중복 과금 완화가 있어도 무제한 재조회 설계에 의존하지 않는다.

**제안:** 초기 20~30명, 월 $30~50의 명시적 지출 상한을 둔 별도 모듈. 결제·토큰·앱 권한과 [개발자 정책](https://docs.x.com/developer-terms/policy)을 확인한 뒤 도입한다. 이번에는 인증 호출이나 구매를 하지 않았으므로 '문서상 구현 가능·사용자 계정에서 미검증' 상태다. 공개 페이지 스크래핑 대행·Nitter 등을 안정적인 기본 경로로 제안하지 않는다.

### Reddit: 승인 전에는 확정 수집원으로 잡지 않음

[2026-06 갱신 Responsible Builder Policy](https://support.reddithelp.com/hc/en-us/articles/42728983564564-Responsible-Builder-Policy)는 API 접근 전 명시적 승인을 요구한다. 상업 목적은 별도 서면 승인이 필요하다. 공개 RSS·JSON이 응답한다는 이유로 승인 절차를 대체하지 않는다.

제안 범위는 LocalLLaMA, MachineLearning, selfhosted, homeassistant, embedded, robotics 등의 기술 커뮤니티 게시글·공개 댓글이다. 이는 **주제 후보 목록**이며 개별 커뮤니티의 현재 운영·수집 승인·품질은 아직 검증하지 않았다. 적용 목적, 저장 기간, LLM 요약 및 제3자 전송 범위, 삭제 반영 방법을 포함해 신청해야 한다. 비용은 계약·승인 조건을 확보하기 전 확정할 수 없다. 이번에는 승인 요청도 전송하지 않았다.

승인 전에는 HN·프로젝트 GitHub Discussions/Issues·공식 포럼·전문가 RSS로 보완한다. 이 대안은 Reddit의 사용자 집단을 그대로 대표하지 않으므로 'Reddit 미포함'을 명시한다.

## 5. OSS는 프로젝트 단위 관측으로 바꿀 것을 제안

현재 지표가 있는 OSS 항목은 3,160개, 고유 URL은 2,873개다. 2개 이상 관측점이 있는 항목은 1,321개지만, 지표 전체 기간이 약 27시간이며 7일·30일 관측을 채운 항목은 0개다. **지금 7일·30일 성장 순위를 제시하지 않는다.**

현행 GitHub 검색은 stars 정렬·최근 push 조건·상위 50개 반환을 사용한다. 검색에 계속 걸리는 프로젝트만 관측되면 작은 신생 프로젝트와 검색 밖으로 밀린 프로젝트의 비교가 왜곡된다. 현 변화량 함수는 과거 기준점이 없을 때 첫 관측값을 쓰므로 실제 관측 기간 표기가 필요하다.

권장 구조:

1. **발견:** 기술별 검색을 일 1~2회, 관련성·신규성 기준으로 후보 발견. 검색식은 채널이 아니라 발견 이유로 보존한다.
2. **고정 관측:** 선정한 200개 내외 저장소를 검색 순위와 관계없이 하루 1회, 급상승 후보만 6시간 간격 관측. 저장소 numeric ID로 통합하고 이름 변경·fork·mirror 구분.
3. **기술 연결:** 프로젝트↔기술↔테마를 별도 관계로 저장. 릴리스·보안 공지는 프로젝트 이벤트로 연결하고 프로젝트 수에 중복 합산하지 않는다.
4. **지표:** stars·forks 절대 증가와 증가율, 릴리스·기여자·이슈 응답·라이선스·보안 상태를 나란히 표시. open_issues만으로 건강성 판정 금지.
5. **순위:** 신규 관찰, 급상승, 꾸준한 성장, 성숙 프로젝트로 구분. 관측 기간 부족·마지막 조회 지연은 배지로 노출. 프로젝트의 출시·push 날짜와 기사 발행일 분리.

검증한 초기 프로젝트 후보:

| 기술·테마 | 프로젝트 | API 확인 |
|---|---|---|
| 로컬·온디바이스 추론 | ggml-org/llama.cpp | JSON·저장소 식별·라이선스 필드 |
| LLM 서빙·효율화 | vllm-project/vllm | 동일 |
| 스마트홈 | home-assistant/core, Koenkk/zigbee2mqtt | 저장소 API / 릴리스 3건 |
| 임베디드·디바이스 OS | zephyrproject-rtos/zephyr | 저장소 API |
| 인프라 관측 | open-telemetry/opentelemetry-collector | 저장소 API |

이들은 수집 경로를 확인한 관측 후보이며 '현재 가장 빨리 성장하는 프로젝트'라는 결론은 아니다. 나머지 테마에는 현재 카탈로그 프로젝트를 우선 연결하고 부족한 분야만 추가한다. 하드웨어·특허 중심 테마에 OSS가 적은 것은 자연스러울 수 있다.

[GitHub 공식 한도](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)는 공개 비인증 60회/시간, 일반 사용자 인증 5,000회/시간이다. [검색 API](https://docs.github.com/en/rest/search/search)는 인증 시 별도 30회/분이다. 200개 저장소×일 4회는 기본 조회 800회/일이며 이슈·기여자 페이지 등의 추가 호출은 별도다. 정규 실행에는 인증·ETag·속도 제한·재시도 지연을 사용한다. API 메타데이터 접근과 코드 라이선스는 각각 확인한다.

## 8. 비용·적용 순서·통과 조건

### 추천 구성

**기본안:** 기존 전문매체·공식 채널 복구 + RSS 전문가·GitHub 고정 관측 + SEC + 제한된 Bluesky/Mastodon. 유료 SNS 없이 시작하며 기존 인프라·LLM 비용은 별도다. API 호출이 무료·공개인 경로도 영구 무료나 무제한 권리를 약속하지 않는다.

**선택안 X:** 기본안에 월 $30~50 상한의 소수 인물 관측 추가. 인물의 글 수가 예산을 넘으면 수집 중단·누락 범위를 표시하고 자동 증액하지 않는다.

**조건부 Reddit/DART:** Reddit 승인, DART 인증키 및 이용 목적 확인 후 추가. 계약·승인 전에는 일정·비용·수집량을 약속하지 않는다.

LLM 비용은 현 실측 토큰·단가 정보가 부족해 금액으로 확정하지 않았다. 초기 제안 처리 예산은 **새로운 고유 관련 항목 500개/일, 탐색 후보 100개/일**이며, 파일럿 유효율과 사용량을 보고 조정한다. 숫자는 현 시스템 용량 측정 결과가 아닌 지출 통제를 위한 시작 제안이다. 모든 등록 소스의 원문을 곧바로 번역하지 않는다.

### 반영 순서

1. **변경안 확정:** source key별 수정안, 저장/요약/표시 범위, 발행 자격, 비용 상한을 검토한다. 기존 데이터·검증 이력 스냅샷과 복구 목록을 준비한다.
2. **작은 변경 묶음:** FreeBSD·Zigbee2MQTT 대체, Infineon·Waymo 경로 제한, 삼성 검증 복구, 핵심 전문매체 처리 우선순위부터 적용한다. 기존 기록을 삭제하지 않고 설정을 되돌릴 수 있게 한다.
3. **24시간 가용성 시험:** 배포 환경에서 파싱·인증·429 처리·중복·날짜를 확인한다. 200만으로 통과시키지 않는다.
4. **7일 품질 시험:** 전후 고유 관련 정보, 날짜 오류, 출처 집중, 토큰 사용량을 비교한다. 7일 OSS 관측 완료 전 해당 순위 비공개.
5. **30일 확장:** 30일 관측을 채운 프로젝트만 장기 추세 공개. 필요한 SNS·업체·지역을 근거 기반으로 확대한다. 저빈도 출처는 별도 관찰한다.

### 제안 통과 기준 — 절대적 업계 기준이 아님

- 공개 후보의 URL·원발행자·콘텐츠 유형·날짜 근거 누락은 검토 대기로 처리.
- 수집 성공률 95% 이상, 잘못된 날짜/목록 페이지의 뉴스 유입 표본 5% 미만, 카드 전 동일 원문 중복 5% 미만을 초기 목표로 삼음.
- 특정 테마의 단일 발행자 비중 30% 초과 또는 독립 발행자 3곳 미만이면 집중 경고. 희소 분야는 이유를 표시하고 자동 제외하지 않음.
- 중요한 이슈는 가능하면 공식 원문 + 독립 검증을 연결. 한 출처만 있는 사건은 '단일 출처'로 표시.
- 제안한 상한 때문에 중요한 기술 사건이 빠지거나 핵심 채널 수집이 24시간 끊기면 확대를 멈추고 해당 변경을 복구. 트렌드 순위는 원시 수치와 보정 수치를 함께 비교.
- 페이지네이션 중단·API 키 만료·삭제 게시물·피드 비어 있음·원문 이동·분류 변경·같은 프로젝트 다중 채널·관측 7일 미충족을 적용 테스트 시나리오에 포함.
- 권리·정책 확인이 끝나지 않은 출처는 자동 LLM 처리·전문 보관을 적용 완료로 선언하지 않음. Julia Evans 등 명시적 의사표시가 있는 경로는 따로 다룸.

## 9. 이번에 제안하는 결정

**기본안부터 적용 준비하는 것을 권한다.** 가장 큰 효과는 새로운 출처 수를 늘리는 것보다 기존 핵심 정보가 처리·분석에 들어오게 하는 데 있다.

검토 가능한 변경 묶음은 다음과 같다.

- **복구:** Samsung KR/Global 검증, IEEE·NVIDIA·OpenAI·Apple 카드 처리.
- **대체·제한:** FreeBSD 사이트맵→공식 RSS, Zigbee2MQTT 기기 DB→릴리스, Infineon·Waymo→뉴스/발표 경로 한정.
- **통합:** HN 중복 검색·Mastodon 태그·동일 프로젝트 중복. 원출처·발견 이유는 보존.
- **추가 후보:** Fowler·Troy Hunt·Schneier·IIJ, GitHub 고정 관측, SEC 공시. 각 경로의 파서·콘텐츠 정책 통과 후 등록.
- **조건부:** X 예산·앱, Reddit 승인, DART 키.
- **보류:** Sony 시험 RSS, 비어 있는 LG 구 RSS, AI 처리 조건 미확정 출처, 7일·30일 미관측 트렌드 순위.

이 보고서는 적용 제안이며 사용자 결정 전 운영 변경은 하지 않는다. 인지도 전수 등급, 개별 기사 정확도 전수 심사, 유료·승인형 API의 계정별 실증은 완료한 것으로 표시하지 않았다.
