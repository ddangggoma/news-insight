## 3. 진행 기록

- **#3 카드화 우선순위 (2026-10-09):**
  - **효율 검토:** 운영 카드 3만 건으로 검토했고, 최신 30%는 검증용으로 뺐다.
    - 유입은 하루 1.7~3만 건인데 카드는 4천~1.1만 건이고, 카드의 35~40%가 무관이었다.
    - 사전 선별 AUC: 출처 이력 0.68, 제목 임베딩 중심점 0.80, **제목 임베딩 리지 회귀 0.85**(출처 이력을 더하면 0.86).
    - 유입의 40%만 카드화할 때 점수순이면 DX 기사의 56%를 확보한다(최신순 40%). 카드 중 DX 비율은 90%(최신순 64%).
    - 제목만으로 테마 예측: 상위 3개 안 65%, 분야 62%.
  - **구현:**
    - `triage_models`·`item_triage` 테이블(마이그레이션 0034).
    - 호스트 카드 작업 앞에 `cards triage`: 신규 제목을 bge-m3로 임베딩하고 점수를 매긴다.
    - 매일 03:50 `cards.triage_train`으로 모델을 다시 학습한다.
  - **점수:** DX 확률 × 노드 우선순위 + 관심 목록 가산 + 6시간 내 가산.
    - 우선순위는 제외·낮음·보통·높음·최우선이다.
    - 테마·분야는 예측 테마로 적용하고, 기술은 제목에 이름·별칭이 나오면 적용한다. 이름이 나오면 확률 하한 0.6을 쓴다.
    - 학습 표본에 출처가 하나뿐이면 분산이 0이라 표준화 값이 폭주한다. 분산에 하한을 두고 표준화 값을 ±3으로 자른다.
  - **선택:**
    - 점수순 90%와 최신순 10%를 섞는다(학습 라벨 편향 방지).
    - 일시정지·폐기 출처와 "제외" 노드는 카드화하지 않는다.
    - DX 확률 0.8 이상은 미검증 출처 일일 상한을 넘는다.
  - **노드 우선순위 설정:** 콘솔 분류 체계(변경 초안·미리보기·되돌리기)에서 한다.
  - **피드백(#2) 제외:** 사용자가 필요할 때 노드 우선순위로 조정한다.
- **#1 근거 기반 질의응답 (2026-10-09):**
  - **색인:** `card_embeddings`(마이그레이션 0035)에 카드의 한국어 제목·요약을 bge-m3로 임베딩한다.
    - 호스트 카드 작업의 `cards run` 뒤에 `cards embed`(회당 2,000건)를 돌려 새 카드를 넣고 기존 카드를 채운다.
    - ANN 색인은 없다. 정확 탐색으로 충분하다(0033과 같은 판단).
  - **검색:** 질문을 같은 모델로 임베딩해 기간·분류 노드(하위 포함) 안에서 가까운 카드 80건을 가져온다.
    - 무관 카드는 빼고, 이슈 묶음(story)당 1건으로 근거 12건을 만든다.
  - **답변:** 로컬 Qwen(LM Studio)이 근거만으로 한국어로 답하고 문장마다 [n]을 단다. 근거가 부족하면 그렇다고 말한다.
    - 근거 속 지시문은 따르지 않는다.
    - API 프로세스당 한 번에 한 질문만 받는다(Qwen이 카드 작업과 공유되므로). 바쁘면 429, 모델이 없으면 503이다.
  - **화면:** 독자 `/ask`(상단·하단 메뉴 "질문").
    - 질문, 기간(1주~1년), 범위(기술·테마 2단계까지)를 고른다.
    - 답의 [n]은 근거 기사로 이어지고, 인용되지 않은 근거는 흐리게 표시한다.
    - 최근 질문 10개는 브라우저에만 남는다.
  - `POST /api/public/ask`는 공개 키를 쓰고 웹의 로그인 관문 뒤에 있다. 질문은 서버에 저장하지 않는다.

    - 키워드(제목·키워드 부분 일치)
    - 의미 검색 문장(카드 임베딩과 코사인 유사도가 일치 정도 이상, 기본 0.50 — 운영 데이터에서 주제 문장에 가장 가까운 카드가 0.55~0.6, 100번째가 0.5)
  - **화면 `/dossiers/{id}`:**
    - 최근 7일 바뀐 점: 건수·직전 7일 대비, 새로 등장한 기업, 신호 유형 증감, 주요 이슈.

    - 관련 기업 상위 12곳, 30일 요약에서 수치가 든 문장 8개.

  - **가설:** 판단 상태는 검토 중·지지됨·기각됨·엇갈림이다.
    - "근거 후보 찾기"는 주제 카드 중 가설 문장과 가장 가까운 8건을 보여 준다(180일). 찬성·반대·참고로 붙인다.
    - 같은 카드를 다시 붙이면 입장이 바뀐다.
  - **API:** `/api/public/dossiers`는 공개 키와 세션 토큰(`X-Session-Token`)을 쓴다. 보관은 삭제가 아니라 상태 변경이다.
  - **성능(배포 후 운영 데이터):** 처음에는 상세 58초, 카드 목록 18초가 걸렸다. 기준의 OR 조건을 시간 정렬·페이지와 한 쿼리에서 걸면 플래너가 시간 색인을 따라 행마다 조건을 검사했기 때문이다. 창 안의 일치 id를 먼저 한 번 구하고(`matched_ids`, 1~2초) 모든 화면이 `id = ANY(:ids)`로 쓰게 바꿔 상세 1.8초, 목록 1.1초, 근거 후보 2.1초가 됐다.
