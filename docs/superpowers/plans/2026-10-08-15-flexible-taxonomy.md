## 0. 목표

- 분야 → 테마 → 기술 3단 고정 구조를 **체계(분류의 종류) + 노드(깊이 제한 없는 트리)** 데이터로 바꾼다. 코드 수정 없이 콘솔에서 새 체계를 만들고, 원하는 가지만 더 깊게 쪼갠다.
- 바꾸는 종류에 따라 비용을 다르게 한다. 깊은 단계 추가·이름 변경·이동·통합·폐지는 LLM 재분류 없이 즉시, LLM이 고르는 깊이의 쪼개기·신설만 해당 가지의 카드를 다시 분류한다.
- 레이더·필터·관심 목록·브리핑·페르소나가 "체계 + 깊이 + 하위 트리"로 집계한다.

### 완료 기준

1. 지금의 분류(분야 12 · 테마 66 · 기술 274 · 신호 유형 · 영향 · 범위)가 체계·노드로 옮겨지고, 이관 전후 집계가 같다.
2. 기존 컬럼과 라벨이 어긋나지 않는다(트리거 이중 기록, 전환 기간).
3. LLM 프롬프트가 DB에서 `llm_depth`까지 조립되고, 그 아래 깊이는 규칙(별칭·키워드)으로 붙는다.
4. 콘솔에서 노드 추가·이름·이동·통합·폐지·쪼개기와 체계 설정 변경을 초안 → 미리보기 → 적용 → 롤백으로 할 수 있다.
5. 레이더·필터·관심 목록이 어느 깊이의 노드든 고를 수 있다.

## 1. 데이터 모델

| 테이블 | 내용 |
|---|---|
| `tax_schemes` | key, 이름, 구조(tree/list), 카드당 최소·최대 개수, `llm_depth`, 깊이별 이름, 쓰는 곳 플래그, 순서, 상태 |
| `tax_nodes` | id(불변), scheme, parent, key(체계 안 유일·불변), 이름, 정의, 포함·제외 기준, 별칭, 속성(JSON: 기술 종류 등), 상태(active·draft·deprecated·merged), merged_into, 순서, `path`(조상 id 배열, 자기 포함) |
| `tax_relations` | 노드 → 노드(다른 체계), 종류 `implies`(파생 라벨) · `related` |
| `tax_revisions` | id, 시각, 작성자, 메모, 변경 내역(JSON), 스냅샷(JSON), 상태(draft·applied·rolled_back) |
| `card_labels` | (item_id, node_id) 기본키, scheme, source(`legacy`·`llm`·`rule`·`derived`·`human`), 확신도, revision |

- 가장 구체적인 노드만 저장하고 상위는 `path`로 계산한다. 노드 id로 집계하므로 이름 변경·이동 후에도 시계열이 이어진다.
- 전환 기간에는 `item_cards`의 기존 컬럼이 정본이고, 트리거가 `source='legacy'` 라벨을 맞춘다. 규칙·파생 라벨(`rule`·`derived`)은 트리거가 건드리지 않는다.

## 2. 분류 파이프라인

- LLM은 체계별 `llm_depth`까지만 고른다(기술 = 2, 지금의 테마). 프롬프트는 DB에서 조립하고 노드별 정의·포함·제외 기준을 넣는다. 미리보기에서 프롬프트 길이 예산(Qwen 16K)을 넘으면 경고한다.
- 그 아래 깊이는 규칙으로: LLM이 고른 가지 안에서 노드 별칭이 카드 키워드·제목과 맞으면 붙인다(SQL 재계산).
- 파생: `implies` 관계로 다른 체계 라벨을 즉시 붙인다.
- 확신이 낮으면 중간 노드(상위)에만 붙이는 것을 허용한다.

## 3. 변경 엔진

| 작업 | 처리 | LLM 재분류 |
|---|---|---|
| 노드 추가(`llm_depth` 아래) | 규칙으로 즉시 | 없음 |
| 이름·정의·별칭 | 즉시(별칭은 규칙 재계산) | 없음 |
| 하위 트리 이동 | path·라벨 집계만 | 없음 |
| 통합 | 라벨 치환, 이전 노드 merged | 없음 |
| 폐지 | 대체 노드로 치환하거나 상위로 | 없음 |
| 쪼개기·LLM 깊이 신설 | 규칙 1차 배정 + 해당 가지 카드만 재분류 대기 | 대상만 |
| 체계 설정(`llm_depth`, 개수) | 영향 계산 | 필요한 카드만 |
| 새 체계 | 파생·규칙 즉시 | 선택 |

초안 → 영향 미리보기(카드 수, 재분류 건수, 예상 시간, 샘플) → 적용(트랜잭션) → 이력·롤백(스냅샷 복원).

## 4. 사용처와 UI

- 레이더: 체계·집계 깊이·기준 노드 선택, 트리맵·선버스트.
- 리더 필터·관심 목록·브리핑·페르소나: 어느 깊이의 노드든, 하위 포함.
- 웹 라벨: `/taxonomy` API(리비전 단위 캐시). 생성 TS 파일은 사용처 전환 뒤 제거.
- 콘솔 "분류 체계": 체계 관리(설정·깊이별 이름), 트리 편집기(react-arborist: 가상화·끌어서 이동·그 자리 이름 변경, 노드별 건수·추세·source 비율), 노드 상세(정의·기준·별칭·관계·대표 기사), 공용 트리 선택기(cmdk), 변경 바(목록·트리 비교·미리보기·적용·롤백·이력), 후보 수신함(미분류 신호 묶음 → 노드에 붙이기), 분포(recharts Treemap).
