### P1. 플랫폼 기반 & 소스 레지스트리 — 상세 계획 작성 완료

- 포트폴리오 쿼터(트랙 100/100/35/25, 지역 하한) 리포트와 V6 쿼터 게이트
- 운영 CLI: `news-insight sources seed | validate | promote | report`

**완료 기준:** `scripts/dev.sh verify` 통과, `docker compose up` 시 전 서비스 healthy, 시드 카탈로그의 Feed 소스가 V0~V3를 실제로 통과하거나 사유와 함께 실패 기록

### P2. 수집 엔진 & 적응형 스케줄러
**요구사항 매핑:** §4 전체, §5 Seen Ledger, §3 V4 자동화 (V5·V6 자동 승격은 P5로 이관, D8)
**상세 계획:** [`2026-10-03-02-collection-engine.md`](2026-10-03-02-collection-engine.md)

- 공통 수집 계약 `Collector.collect(source, state) -> CollectResult[RawItem]` 정의, Feed / JSON API / 선언형 크롤러 어댑터 구현
- 조건부 요청 (ETag / Last-Modified → 304), Redis 기반 도메인별 Rate-limit 예산, 분산 락으로 동일 소스 동시 수집 방지
- 실패 격리: 지수 백오프로 최대 3회 재시도 → Dead Letter 테이블, 재처리 CLI
- Selector Drift 감지 (필수 필드 추출률 급락) → 소스 자동 `paused` 전환 + 사유 기록
- 적응형 주기: PollClass별 범위 (속보 5~15분, 뉴스 15~60분, 커뮤니티 10~30분, 논문 2시간, 특허/OSS 6~24시간). 연속 304나 신규 0건이면 주기 연장, 신규 급증 시 단축. Celery Beat는 1분 tick 디스패처만 맡음
- Seen Ledger: `canonical_url + stable_id + content_sha256` 선검사. 변경이 없으면 저장과 이후 LLM 호출 모두 생략
- 원문 저장 정책 (D9): 등급별 저장 범위 적용, `fulltext_ttl` 본문은 30일 뒤 자동 삭제
- V4 Canary 러너 (24시간: 304율, 429율, 오류율, 지연 p95, 중복률). V3를 통과한 후보 소스도 Canary 모드로 수집하되 V6 전까지 발행 대상에서 제외

**완료 기준:** DLQ·paused 전이·무변경 재수집 시 저장 0건을 통합 테스트로 검증, 약관 검토를 마친 시드 Feed 소스가 실제 24시간 Canary를 수행하고 V4 판정 기록

### P3.6. 수집처 확장 + V1 자동 승인 + 한국어 카드 뉴스 (D17, D18, D19)
**배경:** 카탈로그 292개가 운영 DB에 시드되지 않았고, 모든 소스가 사람의 약관 검토(V1)에서 멈춰 수집 0건이었음 (2026-10-04 사용자 지적)

- **V1 자동 승인 (D17):** `terms_url`이 없는 Feed·JSON API·연구 API·GitHub·ATproto·ActivityPub 소스는 robots.txt가 엔드포인트를 막지 않고 자격 증명이 갖춰지면 V1 자동 통과. 저장은 500자 발췌(`excerpt_allowed`)까지. 크롤러와 `config.manual_review: true`는 기존처럼 수동 검토
- **자동 검증 잡:** `sources.auto_validate` (10분마다 100개) — 후보를 V3까지 올려 Canary 수집 시작. 실패는 24시간 뒤 재시도
- **수집처 확장 (D19):** 트랙·범주별 인기·신뢰 소스 후보를 자동 탐색(피드 autodiscovery + 공통 경로)하고 V0·V2·V3 실검증 통과분만 카탈로그에 추가. GitHub 소스는 토큰 등록 후 자동 활성
- **한국어 카드 (D18):** 모든 수집 항목을 카드(한국어 제목·요약 1~3문장·키워드·출처)로 정리. 호스트 launchd가 10분마다 실행. Antigravity CLI(Gemini Flash, 100건 배치)를 주간 한도 90%까지 쓰고, 한도 소진·오류 시 로컬 Qwen으로 자동 전환
- **콘솔:** 카드 뉴스 화면(필터·검색·키워드), 카드 생성 현황(대기·실패·엔진별·Antigravity 남은 한도), 항목 목록·상세에 한국어 제목

**완료 기준:** 운영 DB에 1,000개 이상 시드, 자동 검증으로 수집 시작, 신규 항목이 10분 내 한국어 카드로 보임

### P3.7. 대상 우선 수집 + 공식 API 대안 + 관련성 검토 (D20)
**배경 (2026-10-04 사용자 지시):** "RSS가 우선이 아니다. 주요 IT 카테고리의 뉴스·SNS·논문 대상을 먼저 정하고, RSS → 안 되면 크롤링으로 모두 매일 수집", "YouTube는 우회 또는 대체 SNS 검토", "관련성은 랜덤 샘플링으로 직접 검토"

- **수집 방법 우선순위:** 대상 사이트마다 RSS(autodiscovery) → 사이트맵(Google News sitemap 우선) → 자동 크롤러 순으로 탐색해 처음 통과한 방법으로 등록
- **자동 크롤러 (`crawler`, `mode: auto`):** 사이트별 선택자 없이 목록 페이지에서 기사 링크를 찾고, 새 기사만 기사 페이지 메타(og/article/JSON-LD/time)로 제목·발췌·날짜를 채움. 날짜 없는 페이지(카테고리)·사이트 공통 제목·제목 접미사 자동 제거. 게시판은 `date_fallback: now`
- **사이트맵 (`sitemap`):** 인덱스에서 뉴스 사이트맵을 골라 제목·날짜를 바로 사용
- **공식 API 대안:** YouTube RSS는 robots.txt가 막아 YouTube Data API(`YOUTUBE_API_KEY`)로 전환. 네이버 뉴스·블로그 검색 API(`NAVER_CLIENT_ID/SECRET`)로 국내 키워드 커버. Reddit·네이버 뉴스 페이지는 robots.txt 전면 차단이라 제외
- **관련성 검토:** 콘솔 "관련성 검토" — seed 기반 재현 가능한 랜덤 표본, 관련/무관/애매 + 메모, 트랙·범주·소스별 관련 비율, CSV 내보내기. P4 관련성 분류의 평가셋으로 사용

### P4. 정규화·중복 제거·클러스터링·분류
**요구사항 매핑:** §5 전체, §9 탐색 축 (분야 15, 테마 75, 사업부, 영향)

### D1 상세: LLM 실행기 배치

**결정 이력:** 1차 검토 때 "성능이 필요한 작업은 Antigravity CLI(`agy`)"로 정했다가, 같은 날 **Qwen 단독**으로 최종 변경했습니다. 외부 LLM으로 데이터가 나가지 않고(§6), 개인 구독 할당량이나 호스트 중계 서비스에 의존하지 않습니다.
