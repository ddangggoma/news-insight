# 기본 페이지 로그인 — 독자 화면 전체를 로그인 뒤로

> 요청(2026-10-06): "기본 페이지 로그인을 위한 내용을 개발 계획 세워주세요."
> 실행 규칙은 [10-execution-progress](2026-10-04-10-execution-progress.md)와 같다(브랜치 → verify → PR → CI → 병합 → `NEWS_INSIGHT-live/scripts/deploy.sh`).

## 0. 요청 해석과 전제

"기본 페이지"를 **독자 화면 전체**(`/` 탐색, `/briefings`, `/radar`, `/digests`, `/items`)로 읽었다. 지금은 로그인 없이 누구나 열 수 있고(`docs/runbooks/reader-web.md`), 로그인은 `/console`에만 있다. 이 계획은 **이미 있는 관리자 매직링크 로그인(P8, D21)을 독자 화면에도 적용**하는 것을 기본안으로 한다. 개인 사용(D20)이므로 새 회원 체계는 만들지 않는다.

다른 해석이면 계획이 크게 달라지므로 §6의 결정이 먼저다.

| 해석 | 범위 | 규모 |
|---|---|---|
| **A. 독자 화면 잠금 (기본안)** | 관리자 1명(또는 허용 목록)만 사이트 전체를 연다. 기존 매직링크·세션 재사용 | S~M |
| B. 독자 계정 (다중 사용자) | 가입·허용 목록·역할(독자/관리자), 사용자별 페르소나·워치리스트·읽음 상태를 서버에 저장 | L |
| C. 로그인 진입점만 | 독자 화면은 공개 유지, 헤더에 로그인/로그아웃·콘솔 링크만 추가 | XS |

## 1. 현재 상태 (출발점)

- **API** `apps/api/src/news_insight/auth/`: `settings.admin_email` 한 주소만 링크를 받는다. 링크 15분 1회용, 세션 14일, SHA-256 해시만 저장, 15분 5회 발급 제한, `/request`는 주소와 무관하게 항상 202.
- **웹** `apps/web/proxy.ts`: `ni_admin` 쿠키가 없으면 `/console*`을 `/login`으로 보내는 낙관적 검사. 실제 검증은 `lib/session.ts`의 `requireAdmin()`(콘솔 레이아웃·액션·라우트).
- **로그인 화면** `app/login/*`: 문구가 "운영 콘솔 로그인", 완료 후 항상 `/console`로 이동, 로그아웃은 `/`로 이동.
- **독자 화면**: 서버 컴포넌트가 `PUBLIC_API_KEY`로 `/api/public`을 부르고 응답을 Next 데이터 캐시(`tags: ["reader"]`)에 둔다. 페르소나·읽기 깊이·배너 닫기는 `localStorage`.
- **로그인 없이 열려야 하는 것**: `/feed.xml`, `/podcast.xml`(RSS·팟캐스트 앱은 쿠키가 없다), `/media/briefings/*.m4a`(Caddy가 직접 서빙, 웹을 거치지 않음), `/internal/revalidate`(콘솔 키로 보호, Caddy가 외부 차단).
- **주의**: 2026-10-06부터 평문 HTTP 포트(8701)도 같은 사이트를 서빙한다. 쿠키는 HTTPS일 때만 `Secure`라서, HTTP로 로그인하면 세션 토큰이 평문으로 오간다.

## 2. 목표와 완료 기준

1. 세션 없이 독자 화면을 열면 `/login?next=<원래 경로>`로 간다. 서버에서도 검증한다(쿠키 위조·만료 세션은 통과하지 못함).
2. 로그인 후 원래 보던 페이지로 돌아간다(같은 브라우저에서 링크를 연 경우). 아니면 `/`.
3. 헤더에 로그아웃(모바일 포함)과 콘솔 링크가 있다.
4. RSS·팟캐스트 구독은 §6-2의 결정대로 계속 동작한다.
5. 기존 콘솔 로그인 가드 E2E가 그대로 통과하고, 독자 E2E는 로그인한 상태로 통과한다.

## 3. 구현 단계

### 3-1. 웹: 가드 (`apps/web`)

- **`proxy.ts`** — matcher를 독자 경로까지 넓힌다. 제외: `/login`, `/login/verify`, `/internal/*`, `/_next/*`, `/icon.svg`, `/favicon.ico`, 그리고 §6-2에서 공개로 정한 피드. 리다이렉트 시 `next`에 경로+쿼리를 싣는다.
  - 먼저 `node_modules/next/dist/docs/`에서 이 버전의 `proxy` matcher 문법(부정 패턴)을 확인한다(`AGENTS.md`).
- **`lib/session.ts`** — `requireAdmin()`에 선택 인자 `next`를 받아 `/login?next=…`로 보낸다. 이름은 그대로 둔다(로그인 주체가 여전히 관리자 1명이므로).
- **`app/(reader)/layout.tsx`** — 서버에서 `requireAdmin()` 호출. 레이아웃은 클라이언트 이동 때 다시 실행되지 않을 수 있으므로, 데이터를 직접 내주는 **라우트 핸들러**(`radar/[period]/[key]/companies/route.ts`, `.../topic/route.ts`)에도 같은 검사를 넣고 실패 시 401.
  - `cookies()`를 읽으면 독자 페이지가 동적 렌더링이 된다. API 응답은 데이터 캐시에 그대로 남으므로 API 부하는 늘지 않고, 페이지당 세션 확인 API 호출 1회가 는다(`last_seen_at` 쓰기는 5분에 한 번). 배포 전후 첫 화면 응답 시간을 비교해 기록한다.
- **`next` 검증** — `/`로 시작하고 `//`·`/\`로 시작하지 않는 같은 출처 경로만 허용(오픈 리다이렉트 방지). `lib/` 순수 함수로 두고 vitest로 테스트.

### 3-2. 웹: 로그인 흐름 (`app/login/*`)

- `requestLogin`: 폼의 숨은 `next`를 검증해 10분짜리 httpOnly 쿠키 `ni_next`에 둔다. 링크에는 넣지 않는다(메일 본문을 바꾸지 않고, 다른 기기에서 열면 `/`로 가는 것으로 충분).
- `completeLogin`: `ni_next`가 있으면 그 경로, 없으면 `/`로 이동하고 쿠키를 지운다(지금은 항상 `/console`).
- `logout`: `/login`으로 이동(독자 화면도 잠기므로 `/`로 보내면 곧바로 다시 리다이렉트된다).
- 문구: "운영 콘솔 로그인" → "로그인", "관리자 이메일" → "이메일", "← 오늘의 브리핑으로" 링크 제거. `verify` 화면 설명도 같은 톤으로.

### 3-3. 웹: 헤더

- `reader-header.tsx`의 테마 토글 옆에 계정 메뉴(`dropdown-menu`): 콘솔 열기, 로그아웃(`logout` 서버 액션 폼). 헤더는 클라이언트 컴포넌트이므로 이메일은 레이아웃에서 prop으로 내려준다.
- 모바일: `bottom-nav.tsx`는 그대로 두고 헤더 메뉴로 충분한지 Pixel 7 E2E에서 확인.

### 3-4. API (`apps/api`)

- 기본안은 **API 변경이 거의 없다**. 독자 데이터는 여전히 웹 서버가 `X-Public-Key`로 가져온다.
- `auth/mailer.py`: 메일 제목·본문의 "관리자 로그인 링크", "운영 콘솔에 접속" → 사이트 전체 로그인 문구. 관련 테스트 갱신.
- §6-1에서 허용 목록을 고르면: `Settings.reader_emails`(쉼표 구분) 추가, `issue_login`이 `admin_email ∪ reader_emails`를 허용, 세션 확인 응답에 `role` 추가, 콘솔 가드는 `role == "admin"`만 통과. 발급 제한은 주소별로 바꾼다.

### 3-5. 피드·오디오 (§6-2 결정에 따름)

- **공개 유지(권장)**: `proxy.ts` 제외 목록에 `/feed.xml`, `/podcast.xml`. 피드에는 브리핑 제목·요약이 실리므로 "잠금"이 완전하지 않다는 점을 런북에 적는다.
- **토큰 피드**: `FEED_TOKEN` 환경 변수, `/feed.xml?token=…`을 `timingSafeEqual`로 비교. 오디오 파일까지 막으려면 Caddy `@audio`에도 쿼리 토큰 검사가 필요하고, 피드 안의 오디오 URL에 토큰을 붙여야 한다.

### 3-6. 운영·보안

- 평문 HTTP 포트(§1 주의): 로그인 화면을 HTTP로 열면 HTTPS로 보내거나, HTTP 세션을 허용하되 위험을 런북에 명시. §6-3.
- `.env.example`, `scripts/check-env.sh`: 새 변수(`READER_EMAILS`, `FEED_TOKEN`)를 고른 경우에만 추가.
- SMTP 미설정 환경에서는 지금처럼 `scripts/dev.sh admin-link`로 링크를 받는다. 배포 전에 운영 SMTP 발송을 한 번 확인한다(독자 화면까지 잠기므로 링크를 못 받으면 사이트 전체를 못 쓴다).
