# R4 독자 웹 설계 — 탐색(시안 B) + 레이더(시안 C)

> **상태:** 설계 확정 (§11). 구현 대기.
> **상위 계획:** [`2026-10-04-05-web-redesign-and-insights.md`](2026-10-04-05-web-redesign-and-insights.md) §6 R4
> **시안:** [`docs/design/mockups/mockup-b-explore.html`](../../design/mockups/mockup-b-explore.html), [`mockup-c-radar.html`](../../design/mockups/mockup-c-radar.html)
> **선행 완료:** R1 디자인 토큰, R2 분류 체계 v1(분야 23·제품군 18·영향 3, `item_labels`·`item_keywords`)

## 1. 목표와 범위

로그인 없이 누구나 여는 독자용 웹을 만든다. **찾기**는 시안 B(패싯 탐색), **흐름 보기**는 시안 C(분야 × 제품군 레이더)로 나눈다.

| 포함 | 제외 (다른 단계) |
|---|---|
| 홈 = 탐색 화면(B), 기사 상세, 레이더(C), 공개 다이제스트·아카이브·RSS | 일 롤업·z-score·정식 수명주기 판정 (R3) |
| 공개 조회 API `/api/public/*` (집계는 실시간 쿼리) | Claude CLI 기간 리포트 서술 (R5) |
| 반응형 3단 → 2단 → 1단, 라이트·다크 | `/console` → `/admin` 이전 (R6) |
| Playwright E2E | 북마크·읽음 표시, 키워드 페이지 (P8 후속) |

**R3과의 관계:** R4의 집계 API는 `items` + `item_labels` + `item_keywords`를 그때그때 GROUP BY 한다. 응답 형태를 R3 롤업 테이블과 같게 정해 두고, R3에서 내부 구현만 롤업 조회로 바꾼다. 그 전까지 "급상승"은 **직전 같은 길이 기간 대비 증감률**로 계산하고 화면에 그렇게 표기한다(z-score 아님).

## 2. 라우트

| 경로 | 화면 | 시안 | 비고 |
|---|---|---|---|
| `/` | 탐색 홈 | B | 기본 기간 7일. 상단에 최신 다이제스트 띠(접기 가능) |
| `/?field=ai&field=display&product=phone&period=7d&q=&sort=` | 필터 상태 | B | 축 안은 OR, 축 사이는 AND. URL이 곧 공유 링크 |
| `/items/[id]` | 기사 상세 | B 시트 | 목록에서 열면 시트(intercepting route), 직접 열면 전체 페이지 |
| `/radar` | → `/radar/week/{이번 ISO 주}`로 리다이렉트 | C | |
| `/radar/[period]/[key]` | 레이더 | C | `day/2026-10-04`, `week/2026-W40`, `month/2026-09`, `quarter/2026-Q3`. 이전·다음 이동 |
| `/digests` · `/digests/[date]` | 공개 다이제스트·아카이브 | — | 기존 `DigestView` 재사용 |
| `/feed.xml` | 다이제스트 RSS | — | 로드맵 P8 요구 |
| `/console/*` | 기존 관리 콘솔 | — | 그대로 (R6에서 `/admin`) |

**App Router 구성** (Next.js 16, `apps/web/app`)

```
app/
  (reader)/layout.tsx              독자 셸: 헤더(기간·검색·테마), 모바일 하단 탭바
  (reader)/page.tsx                탐색 홈
  (reader)/@sheet/default.tsx      평소엔 null
  (reader)/@sheet/(.)items/[id]/page.tsx   목록 위 시트
  (reader)/items/[id]/page.tsx     기사 상세 전체 페이지
  (reader)/radar/page.tsx          리다이렉트
  (reader)/radar/[period]/[key]/page.tsx
  (reader)/digests/page.tsx, [date]/page.tsx
  feed.xml/route.ts
  console/...                      변경 없음
```

`app/page.tsx`(현재 안내 문구)는 `(reader)/page.tsx`로 대체한다.

## 3. 화면 구성

### 3.1 탐색 홈 (`/`)

| 영역 | 내용 | 데이터 |
|---|---|---|
| 헤더 | 로고, 검색(`/` 단축키), 기간 1일·7일·30일·전체, 레이더 링크, 테마 | — |
| 다이제스트 띠 | 최신 다이제스트 헤드라인 + 인사이트 3개 제목, 전체 보기 링크. 닫으면 그날은 접힌 상태(localStorage) | `/api/public/digests/latest` |
| 패싯 (좌 240px) | 기술 분야 23(상위 10 + 더 보기), 제품군 18(상위 8 + 더 보기), 트랙 4, 지역 5, 영향 3. 각 값 옆에 건수, 0건은 흐리게 | `/api/public/facets` |
| 피드 (가운데) | 적용 필터 칩(개별 해제·모두 지우기), 건수, 정렬(최신·영향·반응 지표), 기사 행 30개씩 + 더 보기 | `/api/public/items` |
| 인사이트 (우 300px) | 급상승 키워드 6(직전 기간 대비), 분야 점유율 7, 영향 분포, 함께 언급된 키워드(누르면 검색) | `/api/public/insights` |

**기사 행:** 분야·제품군 태그 → 한국어 제목(16.5/600) → 요약 2줄(`text-ink-2`) → 영향 배지·반응 지표·지역·키워드. 원문 제목은 상세에서만 보여 준다.

### 3.2 기사 상세 (`/items/[id]`)

태그·영향, 한국어 제목, 원문 제목, 트랙·출처·지역·시각, 한국어 요약, 키워드, **원문 링크**, 같은 분야 기사 4개. 본문 전문은 보여 주지 않는다(저장 등급 정책상 발췌만 저장).

### 3.3 레이더 (`/radar/[period]/[key]`)

| 영역 | 내용 |
|---|---|
| 헤더 | 기간 일간·주간·월간·분기, 기간 표시(예: `2026-W40 · 09.28 – 10.04`), ‹ 이전 · 다음 › |
| KPI 4 | 분석 기사(직전 기간 대비), 신규 키워드(이번 기간 첫 등장 + 독립 출처 3곳 이상), 가장 빠르게 뜨는 칸(최소 건수 이상 중 증가율 1위), 교차 신호 후보(같은 분야·제품 칸에 논문·OSS·커뮤니티·뉴스가 모두 있는 칸 수, P4 전 임시 정의) |
| 히트맵 | 분야(행) × 제품군(열). 기본 상위 12 × 10, "전체 23 × 18" 전환, **"표로 보기"** 전환(접근성). 칸 = 건수 + 직전 기간 대비 ▲▼% |
| 칸 상세 | 건수·증감, 최근 8개 기간 추세, 핵심 키워드(급상승 강조), 트랙 체인, 대표 기사 4, "이 조합으로 탐색" → `/?field=..&product=..&period=..` |
| 분야 모멘텀 | 분야별 건수·증감·8기간 스파크라인·점유율·상태(증가·유지·감소) |
| 관심 대비 실체 | 분야별 산점도: 가로 = 뉴스+커뮤니티 증감률, 세로 = 논문+오픈소스 증감률. 기준 대각선 |
| 키워드 수명주기 | 신규·증가·유지·감소 4열. R3 전에는 직전 4개 기간 건수로 임시 판정 |

과거 기간은 결과가 바뀌지 않으므로 길게 캐시한다(§6).

### 3.4 반응형

| 폭 | 탐색 | 레이더 |
|---|---|---|
| ≥ 1280px | 패싯 · 피드 · 인사이트 3단 | 히트맵 + 칸 상세 2단, 하단 2단 |
| 768–1279px | 피드 · 인사이트 2단, 패싯은 왼쪽 시트("필터 N" 버튼) | 1단, 칸 상세는 히트맵 아래 |
| < 768px | 1단, 피드/인사이트 탭, 하단 탭바(탐색·레이더·다이제스트) | KPI 2×2, 히트맵 기본 상위 8 × 6 + 가로 스크롤(첫 열 고정) |

폭 판단은 레이아웃 단위에선 미디어 쿼리, 카드·패널 내부는 container query를 쓴다.

## 5. 공개 조회 API (`apps/api/src/news_insight/public/`)

콘솔 API와 분리한 **읽기 전용** 라우터. 응답 스키마는 독자에게 필요한 필드만 담는다(소스 키·검증 단계·오류 정보 없음).

| 메서드·경로 | 파라미터 | 응답 |
|---|---|---|
| `GET /api/public/taxonomy` | — | 리비전, 축별 노드(키·라벨·설명) |
| `GET /api/public/items` | `period`(1d·7d·30d·all), `field[]`, `product[]`, `track[]`, `region[]`, `impact[]`, `q`, `sort`, `page`, `size≤50` | `Page[ReaderItem]` |
| `GET /api/public/items/{id}` | — | `ReaderItemDetail` (+ 같은 분야 4건) |
| `GET /api/public/facets` | items와 같은 필터 | 축별 `{key, label, count}`. 각 축의 건수는 **그 축의 선택을 뺀** 나머지 필터로 계산 |
| `GET /api/public/insights` | items와 같은 필터 | 키워드 상위(이번·직전 건수, 증감률, 신규 여부), 분야 점유율, 영향 분포, 동시출현 키워드 |
| `GET /api/public/radar` | `period`(day·week·month·quarter), `key` | KPI, 히트맵(분야 × 제품 건수·직전 건수), 분야 모멘텀(8기간), 산점도 점, 키워드 수명주기 |
| `GET /api/public/radar/cell` | `period`, `key`, `field`, `product` | 칸 상세(8기간 추세, 키워드, 트랙 분포, 대표 기사) |
| `GET /api/public/digests`, `/latest`, `/{date}` | `page` | 기존 다이제스트 스키마 재사용 |

`ReaderItem`: `id, title_ko, title, summary_ko[], keywords[], fields[], products[], impact, track, source_name, region, published_at, first_seen_at, url, metric` (`metric`은 대표 반응 지표 하나, 예: `{name: "stars", delta: 2312}`).

**규칙**
- 기간 경계는 KST. 레이더의 주는 ISO 주(월요일 시작), 분기는 달력 분기. 홈의 1d·7d·30d는 지금부터 거꾸로 센 구간
- 공개 대상: 카드가 `ready`이고 현재 분류 리비전으로 라벨이 붙은 항목. canary 포함 여부는 §11 결정
- 현재 라벨만 집계(`item_labels.superseded_at IS NULL`, `taxonomy_rev = 현재`)
- 키워드 증감은 `item_keywords` 기준, 최소 3건 이상만 순위에 올림. 신규 = 이번 기간 첫 등장 + 독립 출처 3곳 이상
- 집계 단위는 항목. P4 클러스터가 생기면 사건 단위로 바꾼다
- 추가 인덱스: `item_labels (axis, node_key) WHERE superseded_at IS NULL`, `items (first_seen_at)`(이미 있으면 생략)

**접근 경로:** 지금 구조와 같이 웹 서버만 내부망으로 호출한다. Caddy에서 `/api/public/*`도 외부 404로 막고, 키는 콘솔 키와 **별도인** `PUBLIC_API_KEY`를 쓴다. 공개 페이지가 콘솔 키를 쓰지 않게 하려는 것이다.

## 6. 캐싱과 성능

`cacheComponents`는 켜지 않는다(콘솔의 `force-dynamic` 구성과 충돌 위험). 대신 공개 API 호출에 `fetch`의 `next.revalidate`·`next.tags`를 쓴다(Next.js 16 문서 `03-api-reference/04-functions/fetch.md`).

| 데이터 | revalidate | 태그 |
|---|---|---|
| 홈 items·facets·insights | 300초 | `reader-items` |
| 최신 다이제스트 | 600초 | `digest` |
| 레이더: 현재 진행 중인 기간 | 600초 | `radar` |
| 레이더: 끝난 기간 | 86400초 | `radar` |
| taxonomy | 3600초 | `taxonomy` |

- 같은 필터 조합은 서버에서 공유 캐시되므로 공개 트래픽이 API·DB로 바로 가지 않는다
- 긴 피드는 `content-visibility: auto`, 행 30개 단위
- 기사 상세 시트는 목록 화면 유지 상태에서 열리므로 뒤로 가기 시 스크롤이 유지된다

## 7. 접근성

- 패싯은 실제 `<input type="checkbox">` + `<label>`, 키보드만으로 조작 가능
- 시트는 Radix Dialog 기반(포커스 가두기, Esc 닫기)
- 히트맵 칸은 `<button aria-pressed>` + `aria-label="온디바이스 AI × 스마트폰 412건, 전주 대비 41% 증가"`, 표 보기 제공
- 증감은 색만으로 표시하지 않고 ▲▼ 기호와 숫자를 함께 씀
- 대비는 R1 토큰 기준(본문 ≥ 7:1, 보조 ≥ 4.5:1), `prefers-reduced-motion` 준수

## 8. 보안·공개 정책

- 독자 영역은 인증 없음. `/console`·`/api/admin`·`/api/public` 외부 차단은 Caddy에서 유지·추가
- 공개 응답에 본문 전문·운영 정보 없음. 원문은 링크로만 연결
- 검색어는 ILIKE 이스케이프(기존 카드 검색과 같은 방식), 페이지 크기 상한 50
- `robots`: 독자 영역 허용, `/console` 차단. 각 페이지 `generateMetadata`로 제목·설명

## 10. 작업 분해

API와 웹은 응답 스키마를 먼저 고정하면 병렬로 진행할 수 있다. 웹은 고정한 스키마의 JSON 픽스처로 먼저 개발한다.

| # | 작업 | 영역 | 선행 |
|---|---|---|---|
| 1 | 공개 라우터 골격, `PUBLIC_API_KEY` 가드, 독자 스키마, Caddy 차단 | API·ops | — |
| 2 | 기간 키 파싱·KST 경계 유틸 | API | — |
| 3 | `/items` 다중 필터·검색·정렬·페이지 | API | 1 |
