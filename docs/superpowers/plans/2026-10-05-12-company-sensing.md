# 기업 센싱 — 테마별 기업 레지스트리·카드 기업 태그·레이더 기업 인사이트

> 요청(2026-10-05): "업체들의 정보도 센싱하여 … 주요 기업의 활동 모니터링, 새로운 업체의 대두 등 다각도에서 인사이트를 뽑을 수 있도록", "테마별 주요 기업들을 정리 … 카드에서 업체 관련 뉴스나 정보이면 태그를 추가", "레이더에도 어떻게 추가할지 심층 검토하여 인사이트가 될 만한 내용을 정리".
> 실행 규칙은 [10-execution-progress](2026-10-04-10-execution-progress.md)와 같다(브랜치 → verify → PR → CI → 병합 → `NEWS_INSIGHT-live/scripts/deploy.sh`).

## 1. 현재 상태와 출발점

- 카드에는 기업 축이 없다. 대신 키워드(`technology_keys`)에 기업명이 섞여 있다. 최근 30일 상위 150개 키 중 기업·기관이 40개 이상(waymo 985, infineon 695+인피니언 200, renesas 577, anthropic 416, openai 410, qualcomm 407, toyota 394+토요타 203+도요타 93, apple 360, nvidia 146, 삼성전자 150 …). 같은 회사가 한·영·일 표기로 흩어져 있고, 기술 레이더 상위를 기업명이 차지해 기술 신호를 가린다.
- 기관(ITRI 1,065, ENISA 871, USPTO 920, JEDEC 535, A*STAR 491, IMDA 443 …)은 대부분 **자기 채널 소스**(해당 기관 뉴스룸)에서 나온다. 기업도 마찬가지로 공식 뉴스룸 소스가 있으면 언급량이 부풀려진다 → 기업 레이더는 "자사 발표"와 "외부 보도"를 반드시 나눠야 한다(§4-1).

## 2. 데이터 모델

### 2-1. 레지스트리 (`catalog/companies.yaml` → `companies`, `company_aliases`)

| 필드 | 뜻 |
|---|---|
| `key` | 정규화 키(소문자, 공백·하이픈·밑줄·가운뎃점 제거; 기술 레지스트리와 같은 `normalize`) |
| `name` / `name_ko` | 표시 이름(원문 공식 표기) / 한국어 표기 |
| `kind` | `company` · `startup` · `institute`(연구기관) · `regulator`(규제·정부) · `standards_body`(표준·업계 단체) |
| `region` | 본사 지역: `kr` · `us` · `cn` · `jp` · `tw` · `eu` · `other` |
| `relation` | 삼성 DX 기준 관계: `self`(삼성 계열) · `competitor`(완제품 경쟁) · `supplier`(부품·SW 공급) · `partner`(플랫폼·생태계 협력) · `peer`(그 외 주요 플레이어) |
| `themes` | 주력 테마 키 목록(분야__테마, 1~4개) — 테마별 주요 기업 화면과 "새 테마 진입" 판정의 기준선 |
| `domains` | 공식 도메인 — 소스 `official_domain`과 일치하면 자사 발표로 집계 |
| `aliases` | 다른 표기·한국어·일본어·티커 등(정규화되어 저장) |
| `status` | `active` · `watch`(후보 대기열에서 승격 전) · `ignored` |

- 62개 테마마다 최소 6곳(경쟁사·공급사·신흥 업체 포함), 전체 약 400곳으로 시작한다. 콘솔 편집(`edited_in_console`)은 시드 재적용 시 보존(기술 레지스트리와 같은 규칙).
- 모호한 별칭(예: `meta`, `apple`, `arm`, `x`)은 **키워드·LLM 기업 태그 전체 일치**로만 매칭하므로 일반 명사 오탐이 거의 없다. 한 글자·일반어 별칭(`x`, `ai`)은 금지(로더가 거부).

### 2-2. 카드 (`item_cards`)

- `companies` (JSONB, 최대 5): LLM이 뽑은 **기사의 주체·대상 기업·기관명** 원문 표기. 분류 공통 필드(`Classification`)에 넣어 카드 생성과 분류 전용 재분류 모두에서 채운다.
- `company_keys` (JSONB, GIN): `canonical_company_keys(companies, keywords)` — 두 목록을 정규화해 **등록된 별칭만** 레지스트리 키로 바꾼 결과. 기술 키와 같은 방식의 DB 트리거(`companies`·`keywords` 변경 시)로 모든 쓰기 경로가 일치한다. 기존 카드는 마이그레이션에서 키워드 기반으로 즉시 백필된다(LLM 호출 없이 약 30~40% 카드에 기업 태그).
- 등록되지 않은 이름은 `companies`에 원문으로만 남는다 → **신흥 업체 후보**(§4-5)의 원천.

### 2-3. 프롬프트 규칙 (분류 공통)

```
companies: 기사의 주체이거나 직접 대상인 기업·기관 0~5개(공식 표기: Samsung Electronics, TSMC,
  현대자동차, Figure AI). 발행 매체·단순 비교 대상·인물은 넣지 않는다. 없으면 빈 배열.
```

## 3. 레이더 통합 — 심층 검토

레이더는 이미 `field` / `theme` / `keyword` 세 차원을 같은 엔진(`_series` → 8개 기간 계열, 진행 중 기간 보정, z, 생애주기, 트랙·영향·지역 분해, 출처·일 3건 상한, 유효 출처 수)으로 계산한다. **기업을 네 번째 차원 `company`로 추가**하면 아래 지표가 추가 비용 없이 같은 통계 규칙으로 나온다. 그 위에 기업에만 의미 있는 파생 지표를 얹는다.

### 3-1. 기업 차원에서 공짜로 얻는 것 (기존 엔진 재사용)

| 지표 | 해석 |
|---|---|
| 기간별 언급 수·변화율·z·상태(new/surging/rising/steady/falling) | 기업 모멘텀. "이번 주 Qualcomm 급증(z 3.1)" |
| 트랙 분해(연구·OSS vs 뉴스·커뮤니티) | 연구·OSS 비중이 큰 기업 = 기술 축적 단계, 뉴스·커뮤니티 = 시장 반응 단계 |
| 영향(opportunity/risk/watch) 분해 | 그 기업 소식이 DX에 위협인지 기회인지 |
| 지역 분해·지역별 첫 보도 | 해외에선 크게 다루는데 국내 보도 공백인 기업(국내 공백 신호 재사용) |
| 유효 출처 수(1/HHI)·상한 집계 | 한두 매체가 몰아 쓴 소음 걸러내기 |

### 3-2. 기업 고유 인사이트 (새로 계산)

1. **자사 발표 vs 외부 보도 (self share)** — 소스 도메인이 그 기업의 `domains`에 속하면 자사 발표. 외부 보도 비율이 오르면 "시장이 주목하기 시작", 자사 발표만 많으면 "홍보 공세". 모멘텀 순위는 기본으로 **외부 보도 기준**(자사 채널 부풀림 제거).
2. **활동 구성 변화 (activity mix shift)** — 기업별 신호 유형(launch·market·finance·supply·ip·regulation·research·standard·security_event·ecosystem) 분포의 현재 기간 vs 기준선. 비중 변화가 가장 큰 유형을 한 줄로: "Apple: 특허·소송(ip) 비중 8%→31%", "TSMC: 공급망(supply) 급증". 경쟁사 전략 전환의 가장 빠른 단서.
3. **테마별 점유(share of voice)와 리더 교체** — 테마마다 기업 언급 점유율 상위 5곳, 이전 기간 대비 1위 교체·점유율 ±10%p 변동 표시. "온디바이스 AI: Qualcomm 34%→22%, MediaTek 12%→25%".
4. **새 테마 진입 (theme entry)** — 기업×테마 조합이 이번 기간 3건 이상인데 기준선 기간 0건이고 레지스트리 주력 테마에도 없으면 진입 신호. "OpenAI → 디바이스 OS(platform_sw__device_os) 첫 진입". 사업 확장·피벗 탐지.
5. **신흥 업체 (new entrants)** — 두 경로:
   - 등록 기업: 첫 언급이 최근 3개 기간 안(데뷔).
   - 미등록 이름: LLM `companies` 원문 중 이번 기간 3건 이상·출처 2곳 이상·지난 90일 언급 0건. 콘솔 후보 대기열에도 올려 레지스트리 승격.
6. **동시 언급 네트워크 (co-mention)** — 같은 카드에 함께 나온 기업 쌍, lift(우연 대비 배수)와 신규 쌍 여부, 그 쌍 카드의 주된 신호 유형(market=제휴·M&A·경쟁, supply=공급 계약, ip=분쟁). "Samsung × Google 신규 쌍, 주 유형 market".
7. **경쟁사 위험 지도** — relation=competitor 기업들의 이번 기간 risk 비중·launch 건수 한눈에(삼성 DX 관점 경쟁 압력).
8. **기업 × 기술** — 기업 상세에서 그 기업과 함께 언급된 기술 키 상위(기술 레지스트리 키만) + 이번 기간 새로 붙은 기술. "Meta: 새 기술 — AI 글래스, 뉴럴 밴드".

### 3-3. 레이더 신호(radar_signals)에 추가할 톤

기존 `public/signals.py` 규칙과 같은 소량 표본 통계(포아송 z, 최소 출처 2)로 판정하고, 04:40 스냅숏 → 브리핑·전략 근거로 자동 흘러간다.

| 톤 | 조건 | 예시 문구 |
|---|---|---|
| `company_surge` | 기업 상태 surging, 외부 보도 기준 | "Qualcomm 언급 급증(z 3.1, 출처 9곳) — 주 유형 launch" |
| `company_shift` | 활동 구성 중 한 유형이 +20%p 이상, 현재 5건 이상 | "Apple 특허·소송 비중 8%→31%" |
| `theme_entry` | §3-2-4 | "OpenAI, 디바이스 OS 테마 첫 진입(4건)" |
| `new_entrant` | §3-2-5 미등록 이름 | "신흥: Physical Intelligence — 6건·출처 4곳, 휴머노이드" |

### 3-4. 화면

- **레이더 > 기업 탭(새 섹션)**: ① 기업 모멘텀 표(상태·z·외부 보도 비율·관계 배지·주 유형) ② 테마별 점유 히트맵(테마×상위 기업, 리더 교체 표시) ③ 신흥 업체·새 테마 진입 카드 ④ 동시 언급 쌍 목록 ⑤ 경쟁사 위험 지도(risk 비중 × launch 건수 산점도).
- **기업 상세(토픽 상세 kind=company 재사용)**: 기간 계열, 활동 구성 변화 막대, 테마 분포, 함께 언급된 기술·기업, 대표 스토리.
- **카드**: 기업 칩(레지스트리 이름, 관계 색) → 클릭 시 리더 피드를 기업으로 필터.
- **테마 상세**: 그 테마의 주요 기업(레지스트리) + 이번 기간 점유 상위.

### 3-5. 하지 않는 것 / 주의

- 주가·재무 데이터는 쓰지 않는다(유료 API 불가, 사용자 결정).
- 기관(institute/regulator/standards_body)은 기업 모멘텀 순위에서 기본 제외(필터로 포함 가능) — 자기 채널 소스가 많아 순위를 왜곡.
- 레이더 응답 크기 예산(≤400KB, C4) 유지: 기업 섹션은 상위 40곳·쌍 24개로 자르고 아래 패널은 지연 렌더링.
